  - eyebrow: 03 / Key Decisions
    title: Increase throughput without losing control.
    layout: decisions
    intro: |
      The architecture evolved during delivery. I invested in leverage, proved new capabilities incrementally and used observed failures to decide which controls actually helped.
    children: |
      1. **Invest while meeting the deadline.**
         I built the harness while delivering real tickets, not as a separate tooling project. Reusing the prior analysis harness and behavioral tests reduced the risk of investing within a fixed 30-day window.
      2. **Prove before scaling.**
         I designed for parallelism but proved useful sequential throughput first. One worktree and isolated test context per ticket then supported independent execution and validation during the same delivery window.
      3. **Enforce what can be verified.**
         I moved strict output requirements toward deterministic interfaces, while replacing brittle keyword scope checks with contextual agent judgment. Objective validation remained mandatory; stronger prompts were not a substitute for verifiable controls.
      4. **Engineer recovery.**
         Bounded retries and human escalation restored progress on individual tickets. Separately, Langfuse evidence, debugging agents and targeted fixes addressed recurring harness weaknesses—not an assumption of unattended recovery.

      ### What changed in my engineering approach

      During the 30-day period, I corrected two brittle controls. Prompting agents to produce structured files gave way to Codex's deterministic structured-output interface once its availability and suitability became clear. Rigid keyword checks could not reliably interpret scope intent, so I allowed contextual agent judgment while preserving deterministic checks for genuinely verifiable requirements.

      In this organizational context, explicit controls helped establish confidence in an unfamiliar delivery model. But excessive deterministic checks became brittle when the underlying decision required interpreting intent.

      My subsequent harness designs became thinner: preserve strict validation for genuinely verifiable requirements, while allowing agents more flexibility in implementation and reasoning. This later philosophy was a result of the experience, not the architecture I started with.
